# 0003. OpenRouter для качественных прогонов, Ollama для fallback

- Статус: accepted
- Дата: 2026-09-05

## Контекст

Локальная `qwen3:1.7b` достаточна для проверки связности стенда, но её качество и
скорость не подходят для содержательных agentic red-team экспериментов. В
корневом `.env` доступен `OPENROUTER_API_KEY`.

## Решение

OpenRouter становится профилем по умолчанию при наличии ключа и используется для
атакуемого агента, будущих planner/mutator и semantic judge. Конкретные model slug,
лимиты и параметры закрепляются для каждого эксперимента. Ollama сохраняется как
явный локальный профиль для smoke, offline-разработки и резервного демо.

LLM не используется в executor, управлении состоянием, IAM-проверках,
programmatic oracles и расчёте метрик.

## Последствия

Качественные прогоны расходуют внешний бюджет и зависят от провайдера, поэтому
мы журналируем token usage/cost, ограничиваем число шагов и сохраняем replay.
Секрет остаётся только в игнорируемом `.env` и окружении `agent-api`.

## Альтернативы

- Только Ollama: дёшево и автономно, но слабая исследовательская валидность.
- Только OpenRouter: проще конфигурация, но нет offline fallback для демо.
- LLM во всех компонентах: снижает воспроизводимость и доказательность.
