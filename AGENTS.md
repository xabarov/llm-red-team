# AGENTS.md

## Назначение

Этот репозиторий — рабочее пространство команды хакатона. Пользовательские указания имеют приоритет над этим файлом.

## Контекст перед работой

Читайте только то, что относится к задаче:

1. `.codex/project-memory.md` — короткое текущее состояние проекта.
2. `tasks/active/README.md` — единственный список активной работы.
3. `docs/brief.md` — нормализованное ТЗ после его заполнения.
4. Профильный документ из `docs/`, `research/` или `infra/` — по необходимости.

Не загружайте `tasks/archive/`, исходные PDF и полные OCR-тексты без прямой необходимости.

## Рабочий цикл

- Перед изменениями проверьте `git status` и не затрагивайте несвязанные правки.
- Для новой существенной работы заведите один пункт в `tasks/active/README.md`.
- Фиксируйте устойчивые решения отдельными ADR в `docs/decisions/`; не превращайте память проекта в журнал событий.
- После значимой работы обновите текущий статус, ближайшие шаги и блокеры в `.codex/project-memory.md`.
- Завершённую задачу переносите в датированный файл `tasks/archive/YYYY-MM.md` и удаляйте из active.
- Проверяйте только изменённую область; команды проверки документируйте рядом с компонентом.

## Качество и безопасность

- Сначала воспроизводимый минимальный результат, затем оптимизация.
- Не коммитьте секреты, токены, персональные данные, большие бинарные артефакты и временный OCR.
- Red-team проверки выполняйте только на явно разрешённом стенде и в пределах зафиксированного scope.
- Для фактов из публикаций сохраняйте ссылку, библиографию и страницу/раздел источника.
- Для статьи создавайте компактный русский разбор, а не полный машинный перевод: суть, методика, результаты, ограничения, применение к хакатону и карта страниц.

## Команды проекта

- `make doctor` — проверить локальные зависимости.
- `make context-check` — проверить размер файлов, автоматически попадающих в контекст Codex.
- `docker compose config` — проверить Compose-конфигурацию после появления сервисов стенда.
